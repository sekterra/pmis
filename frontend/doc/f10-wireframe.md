# F10 역할 화면 정리

기준은 `users-roles-wireframe.md` 1절·3절과 F10 지시서다. 지시서가 초안보다 구체적인 곳은 지시서를 따른다.

## 목록

- 검색: 검색어(코드·이름), 사용 여부. 전체는 `useYn`을 보내지 않는다. [조회] [초기화].
- 열: 코드, 역할명, 정렬, 사용자 수, 사용 여부, 작업. 정렬은 코드, 역할명, 정렬만 서버 정렬.
- 사용 중지 행은 흐리게. 행 클릭 또는 [상세]로 Drawer.
- [+ 역할 등록]은 CREATE.
- `TENANT_ADMIN` 행은 삭제 버튼을 숨기고 보호 역할이라고 표시한다.
- 삭제는 확인창. `ROLE.IN_USE`, `ROLE.PROTECTED`는 서버 메시지. 복구는 UPDATE이고 사용 중지 행에만.

## Drawer

- 넓은 Drawer, 탭은 기본 정보와 권한.
- 등록: 기본 정보만 쓸 수 있다. 권한 탭은 비활성이고, 저장 후 설정할 수 있다고 안내한다. 저장하면 같은 Drawer가 수정 모드가 되고 권한 탭이 열린다.
- 기본 정보: 역할 코드는 등록만 입력하고 `^[A-Z][A-Z0-9_]{1,49}$`를 폼에서 먼저 검사한다. 수정은 읽기 전용. 역할명 필수, 정렬, 설명, 이름 번역. 수정 본문에는 코드가 없다.
- `TENANT_ADMIN`은 이름·설명 수정이 되고, 삭제는 불가라는 안내를 보인다.

## 권한 표

- 탭을 처음 열 때 `GET /roles/{rolePk}/permissions`. 역할이 바뀌면 다시 호출한다.
- 행은 응답에 나온 `menuCode` 순서, 이름은 `menuName`. 열은 응답의 `actionCode` 합집합을 READ, CREATE, UPDATE, DELETE, EXPORT 다음에 나머지를 붙인다. 열 이름은 로컬 문구이고 없는 코드는 코드 그대로. 없는 칸은 비운다.
- READ가 아닌 기능을 켜면 같은 메뉴 READ도 켠다. READ를 끄면 나머지를 끈다. 메뉴 이름을 누르면 그 메뉴를 모두 켜거나, 이미 모두 켜져 있으면 모두 끈다. 열 머리 전체 선택은 없다.
- 변경이 없으면 권한 저장은 비활성. 저장 본문은 켜진 `permissionCode` 전체. 성공하면 표를 다시 불러오고, 권한은 즉시 반영되지만 메뉴는 다음 로그인 또는 새로고침 때 바뀐다고 안내한다.
- `ROLE.READ_REQUIRED`의 `fieldErrors` 필드(메뉴 코드)는 그 행 옆에 표시한다. `PERMISSION.NOT_FOUND`와 `ROLE.PROTECTED`는 알림(서버 메시지 우선).
- [되돌리기]는 마지막으로 불러온 상태로 돌린다.
- 편집은 `can('ROLE','UPDATE')`. 없거나 `TENANT_ADMIN`이거나 사용 중지면 체크박스를 끄고 이유를 한 줄 안내한다.
- 변경 중 Drawer를 닫거나 탭을 옮기면 버릴지 묻는다.
- 메뉴 이름 검색은 화면에서만 거르고, 저장할 변경은 유지한다.

## 오류

- `ROLE.DUPLICATE`는 역할 코드 칸. 그 밖 `fieldErrors`는 해당 칸. 나머지는 서버 `errorMessage`, 없으면 로컬 문구.
- 저장 중에는 버튼을 비활성화한다.

## 초안과 다른 점 (지시서가 정한 것)

- 초안은 `TENANT_ADMIN` 권한 편집 버튼을 숨긴다. 지시서는 표를 읽기 전용으로 보이고 이유를 안내한다.
- 초안은 행 머리 전체 선택이다. 지시서는 메뉴 이름 칸이다.
- 초안은 메뉴 이름을 서버 번들이라고만 적는다. 응답 `menuName`을 쓰고 기능 열 이름은 로컬 문구다.
- 되돌리기, 변경 중 확인, 메뉴 이름 필터, 등록 후 권한 탭 열기는 지시서에만 있다.
