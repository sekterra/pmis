# F2 수동 확인

환경변수는 이름만 적는다. 값, 주소, 계정, 토큰, 임시 비밀번호는 적지 않는다.

플랫폼 개발 서버는 `npm run dev:platform`이다. 테넌트 개발 서버(`npm run dev`)와 동시에 띄울 때는 포트를 명령 환경에서만 바꾼다. 설정 파일에 포트를 고정하지 않는다.

사용하는 이름: `DEV_BACKEND_URL`, `APP_MODE`. 플랫폼 요청에는 `DEV_TENANT_CODE`가 있어도 `X-Tenant-Code`를 붙이지 않는다.

## 플랫폼 콘솔

1. 플랫폼 로그인 화면 제목이 `PMIS 플랫폼 콘솔`인지 확인한다. 아이디, 비밀번호, 로그인 버튼과 언어 선택이 있다. 언어는 한국어와 English만 바뀌고, 언어 목록 API를 호출하지 않는다.
2. 비밀번호 변경이 필요한 계정이면 로그인 직후 비밀번호 변경 화면만 열린다. 현재 비밀번호와 새 비밀번호를 보내고, 규칙 위반은 서버 `fieldErrors`로 해당 칸에 표시된다.
3. 변경 후 왼쪽 메뉴는 `테넌트 관리` 하나다. 헤더에는 언어 선택과 운영자 이름, 비밀번호 변경, 로그아웃이 있다.
4. 테넌트 목록에서 검색어와 상태로 조회한다. 코드, 이름, 상태, 프로비저닝 단계, 기본 도메인, 생성일이 보인다. 값이 없으면 `-`다. 헤더 정렬은 코드, 이름, 상태, 생성일만 된다. `테넌트 등록`으로 등록 화면에 간다.
5. 등록 화면에 코드, 이름, 기본 언어, 시간대(기본 `Asia/Seoul`), 계약 시작, 계약 종료, 관리자 이름, 관리자 이메일, 도메인을 입력한다. 스키마명은 없다. 등록 중에는 로딩이 유지된다.
6. 성공하면 임시 비밀번호 창에 응답의 `adminLoginId`와 임시 비밀번호가 한 번 보인다. 입력 이메일을 아이디로 바꾸지 않는다. 복사한 뒤 닫으면 비밀번호가 화면에서 사라지고 상세로 이동한다. 주소, 저장소, 로그에 남기지 않는다. 이미 계정이 있어 임시 비밀번호가 없으면 안내 문구와 아이디만 보인다.
7. 상세의 기본 정보에서 이름, 언어, 시간대, 계약 기간, 프로비저닝 단계, 마지막 마이그레이션을 확인한다. 도메인 탭에서 기본 도메인 표시, 추가, 삭제를 확인한다.
8. `ACTIVE`만 중지(사유 필수), `SUSPENDED`만 재개, `FAILED` 또는 `PROVISIONING`만 프로비저닝 재시도가 보인다. 임시 비밀번호 재발급은 확인 후 같은 일회 창에 `adminLoginId`와 임시 비밀번호를 함께 보여 준다.
9. 마지막 도메인 삭제는 `409 TENANT.LAST_DOMAIN`, 사용 중인 도메인 추가는 `409 TENANT.DUPLICATE`, 맞지 않는 상태 변경은 `409 TENANT.INVALID_STATUS_TRANSITION` 서버 메시지로 보인다.

## 만든 테넌트로 테넌트 앱 확인

테넌트 앱은 `npm run dev`로 띄운다. 등록한 도메인으로 접속하는 절차는 백엔드 개발 환경의 Host 규칙을 따른다.

1. 임시 비밀번호로 로그인하면 비밀번호 변경 화면만 열린다.
2. 변경 후 새로고침하면 세션이 유지된다.
3. 다른 탭에서 로그아웃하면 이 탭도 로그인으로 간다.
4. 언어를 바꾸면 화면 문구가 바뀌고, 다시 들어와도 선택한 언어가 유지된다.
