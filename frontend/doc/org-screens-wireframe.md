# 조직 화면 와이어프레임 (회사·부서·사람)

작성: 설계 담당(Claude), 2026-10-22. 검토: 사용자. 개발: Cursor.
기준: `backend/common/doc/api/mdm-api.md` "조직·사람" 절, 기존 화면(공통코드, 다국어, 언어) 패턴.
이 문서가 합의되면 FE 지시서(F7 회사, F8 부서, F9 사람)를 단계별로 쓴다. 합의 전에는 Cursor 에 넘기지 않는다.

## 1. 공통 규칙

- 구성: 검색 영역(위) → 목록(ProTable) → 등록/수정은 오른쪽 Drawer. 공통코드 화면과 같은 방식이다.
- 권한: 화면 진입은 `READ`. 버튼은 `can(메뉴, 기능)` 하나로 판단한다. 등록 `CREATE`, 수정·복구 `UPDATE`, 삭제 `DELETE`. 권한이 없는 버튼은 숨긴다.
- 삭제는 논리 삭제(사용 중지)다. 확인 대화상자 후 호출하고, 사용 중지 행은 회색으로 보이며 "복구" 버튼이 나온다. 검색의 "사용 여부"는 전체/사용/중지(기본 전체).
- 이름 번역: 공통코드 화면의 번역 입력 표(`TranslationEditor`)를 재사용한다. 지원 언어 중 필요한 언어만 입력한다.
- 코드 값 선택(회사 유형, 부서 유형, 고용 유형, 재직 상태, 직위, 직책): `useCodeOptions(그룹)` 으로 현재 언어 이름을 보여 주는 Select. `POSITION`, `JOB_TITLE` 은 시드 값이 없어 비어 있을 수 있다. 이때 Select 는 비활성이고 "공통코드에서 값을 먼저 등록하세요" 안내를 보인다.
- 오류: 서버 `fieldErrors` 는 해당 입력칸에 표시하고, 409 업무 오류(예: `COMPANY.HAS_ACTIVE_DEPT`)는 서버 메시지를 그대로 알림으로 보여 준다. `traceId` 표시는 기존 방식.
- 코드(회사 코드, 부서 코드)는 등록 때만 입력하고 수정에서는 읽기 전용이다.

## 2. 회사 화면 (`COMPANY`)

```
┌ 회사 ─────────────────────────────────────────────────────────┐
│ [검색어____] [유형 ▼] [사용 여부 ▼]            [조회] [초기화] │
├───────────────────────────────────────────────────────────────┤
│                                            [+ 회사 등록]      │
│ 코드  │ 회사명 │ 약칭 │ 유형 │ 상위 회사 │ 국가 │ 정렬 │ 사용 │ 작업 │
│ ACME  │ 에이씨엠이 │ ACME │ 자사 │ -   │ KR  │ 1  │ 사용 │ 수정 삭제 │
│ ...                                        < 1 2 3 > 20/page │
└───────────────────────────────────────────────────────────────┘
```

- 검색: `keyword`(코드·이름·약칭), `companyTypeCode`, `useYn`. 정렬 가능 열: 코드, 회사명, 정렬.
- 등록/수정 Drawer 필드: 회사 코드(등록만), 회사명(필수), 약칭, 유형, 사업자등록번호, 국가(Select, `/nations`), 상위 회사(검색형 Select, 사용 중 회사만, 자기 자신 제외), 정렬 순서, 이름 번역 표.
- 상세 응답의 `translations` 를 수정 때 채우고, 저장 때는 입력된 언어만 보낸다(없는 언어는 서버가 그대로 둔다).
- 삭제 거절 사유(하위 회사, 사용 중 부서, 현재 소속, 마지막 자사)는 서버 메시지로 안내한다.

## 3. 부서 화면 (`DEPT`)

```
┌ 부서 ─────────────────────────────────────────────────────────┐
│ 회사 [ACME ▼]  기준일 [2026-10-22]  [☐ 종료된 부서 포함]  [조회] │
├───────────────────┬───────────────────────────────────────────┤
│ ▾ 본사            │ 개발1팀                  [하위 부서 추가] [수정] [종료] │
│   ▾ 개발본부      │ ┌ 기본 정보 | 변경 이력 | 소속 인원 ┐          │
│     · 개발1팀 ◀   │ 코드 DEV1  유형 팀  상위 개발본부              │
│     · 개발2팀     │ 유효기간 2026-01-01 ~ (없음)  레벨 3  정렬 1   │
│   · 경영지원      │ 이름 번역: ko-KR 개발1팀 / en-US Dev Team 1   │
│ [+ 최상위 부서]   │                                               │
└───────────────────┴───────────────────────────────────────────┘
```

- 왼쪽: `GET /departments/tree` 결과를 트리로 표시한다(전위 순회 배열을 `deptPath` 로 중첩 변환). 회사 선택이 바뀌면 다시 조회한다. 종료된 부서는 회색 + "종료" 표시. 기준일을 바꾸면 그 날짜의 조직을 보여 준다(과거 조직도 재구성은 서버가 하지 않으므로 서버 규칙 그대로).
- 오른쪽 탭
  - 기본 정보: 읽기 화면. 수정은 Drawer.
  - 변경 이력: `GET /departments/{id}/history`. 열: 변경 유형(생성/개명/이동/종료/재개), 적용일, 변경 전후 이름, 변경 전후 상위, 사유, 변경 시각. 수정·삭제 없음.
  - 소속 인원: `GET /people?deptPk=` (주 소속 기준 사람 목록, 이름·직위·재직 상태). 행을 누르면 사람 화면으로 이동한다.
- Drawer 필드: 부서 코드(등록만), 부서명, 유형, 상위 부서(트리 선택, 같은 회사의 사용 중 부서, 자기·하위 제외), 정렬, 유효 시작일, 유효 종료일, 번역 표. 수정에서 이름 또는 상위가 바뀌면 "적용일(기본 오늘)"과 "변경 사유" 칸을 보여 준다.
- "종료"는 삭제와 같다. 종료일을 오늘로 하고 이력을 남긴다는 문구로 확인 대화상자를 띄운다. 종료된 부서는 "재개" 버튼(복구).
- 부서가 하나도 없을 때: "최상위 부서를 등록하세요" 안내.

## 4. 사람 화면 (`PERSON`)

```
┌ 사람 ─────────────────────────────────────────────────────────┐
│ [검색어____] [회사 ▼] [부서 ▼(트리)] [고용 유형 ▼] [재직 상태 ▼] [사용 여부 ▼] │
├───────────────────────────────────────────────────────────────┤
│                                              [+ 사람 등록]     │
│ 이름 │ 이메일 │ 휴대전화 │ 회사 │ 부서 │ 직위 │ 사원번호 │ 재직 상태 │ 사용 │
│ 홍길동 │ hong@… │ 010-… │ ACME │ 개발1팀 │ 과장 │ E0001 │ 재직 │ 사용 │
└───────────────────────────────────────────────────────────────┘
행 클릭 → 오른쪽 넓은 Drawer
┌ 홍길동 ───────────────────────────────────────── [삭제] ┐
│ [기본 정보] [소속] (프로필 이미지는 기본 정보 안)         │
│ ┌ 소속 탭 ───────────────────────────────────────────┐ │
│ │ [+ 소속 추가]                                        │ │
│ │ 회사 │ 부서 │ 직위 │ 직책 │ 사원번호 │ 기간 │ 주 │ 상태 │ 작업(수정·종료·삭제) │
│ └────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────┘
```

- 목록의 회사·부서·직위·사원번호·재직 상태는 서버가 주는 "주 소속 요약"을 그대로 쓴다. 주 소속이 없으면 `-`.
- 기본 정보 탭 필드: 이름(필수), 이메일(형식만 검사, 중복 허용), 휴대전화, 이름 번역 표, 프로필 이미지(업로드·삭제, 이미지 파일만). 프로필 이미지는 9.4 API를 쓰고 미리보기는 `GET /people/{id}/profile-image` 를 쓴다.
- 소속 탭
  - 목록: 과거 소속 포함, 시작일 내림차순, "사용 여부" 필터.
  - 추가/수정 폼: 회사(필수), 부서(선택, 선택한 회사의 부서만), 고용 유형, 재직 상태, 직위, 직책, 사원번호, 시작일(필수), 종료일, 부서장 여부(부서가 있을 때만 켤 수 있음), 주 소속 여부.
  - "종료": 종료일(기본 오늘)과 재직 상태(기본 퇴직)를 입력받는 작은 대화상자. 이미 종료된 소속에는 버튼이 없다.
  - 첫 소속은 서버가 주 소속으로 만든다(체크 비활성 + 안내). 다른 소속을 주 소속으로 바꾸면 기존 주 소속이 해제된다는 안내 문구를 둔다.
  - 퇴직 상태는 종료일이 필수라는 점을 폼에서 먼저 검사한다.
- 사람 삭제가 막히는 경우(현재 소속, 사용 중 계정)는 서버 메시지를 그대로 보여 준다.
- 사용자 계정과의 연결은 사용자 화면 단계에서 다룬다. 이 화면은 읽기만 한다.

## 5. 단계 분할 제안

| 단계 | 내용 |
| --- | --- |
| F7 | 서비스 계층(`services/mdm/org*.ts`, 타입), 메뉴 라우트 연결, 회사 화면 |
| F8 | 부서 트리·상세·이력 화면 |
| F9 | 사람 목록·기본 정보·소속·프로필 이미지 |

각 단계가 끝나면 보고서를 검토하고 수동 확인 문서를 만든다. 첨부 파일(사람·회사·부서·팀)과 팀 화면은 이 묶음 뒤에 따로 한다.

## 6. 합의가 필요한 항목

1. 부서 화면을 트리 + 상세 탭 구성으로 할지, 단순 목록으로 할지.
2. 사람 상세를 Drawer + 탭으로 할지, 별도 페이지로 할지.
3. 프로필 이미지를 F9 에 넣을지, 뒤로 미룰지.
4. 단계를 F7/F8/F9 세 번으로 나눌지, 한 번에 할지.
