# 사용자·역할 화면 와이어프레임 (F10 초안)

작성: 설계 담당(Claude), 2026-10-22. 검토: 사용자. 개발: Cursor.
기준: `backend/common/doc/api/mdm-api.md` "사용자·역할·권한" 절, 조직 화면(F7~F9) 패턴.
이 문서가 합의되면 F10 지시서를 쓴다. 합의 전에는 Cursor 에 넘기지 않는다.

## 1. 공통

- 조직 화면과 같은 방식: 검색 영역 → 표 → 오른쪽 Drawer. 권한 판정은 `can(메뉴, 기능)`. 삭제는 논리 삭제, 복구 버튼은 사용 중지 행에만.
- 메뉴 코드: 사용자 `USER`, 역할 `ROLE`. 권한(`PERMISSION`) 관리 화면은 이번에 만들지 않는다(아래 6절).
- 로그인한 본인에 대한 잠금·휴면·삭제·역할 변경·초기화는 서버가 `USER.SELF_OPERATION_FORBIDDEN` 으로 막는다. 화면은 본인 행에서 그 버튼을 숨기거나 비활성으로 하고 이유를 안내한다.
- 마지막 관리자 보호(`USER.LAST_ADMIN`)와 `TENANT_ADMIN` 역할 보호(`ROLE.PROTECTED`)는 서버 메시지를 그대로 보여 준다.

## 2. 사용자 화면 (`USER`)

```
┌ 사용자 ───────────────────────────────────────────────────────┐
│ [검색어(아이디·사람)] [상태 ▼] [계정 유형 ▼] [역할 ▼] [사용 여부 ▼] [조회] [초기화] │
├───────────────────────────────────────────────────────────────┤
│                                              [+ 사용자 등록]   │
│ 아이디 │ 사람 │ 계정 유형 │ 상태 │ 역할 │ 마지막 로그인 │ 비밀번호 변경 필요 │ 사용 │
│ hong   │ 홍길동 │ 일반 │ 정상 │ 관리자, 조회 │ 2026-10-22 │ - │ 사용 │
└───────────────────────────────────────────────────────────────┘
행 클릭 → 오른쪽 Drawer
┌ hong ──────────────────────────────── [잠금] [휴면] [비밀번호 초기화] [삭제] ┐
│ [기본 정보] [역할]                                                │
└─────────────────────────────────────────────────────────────────┘
```

- 목록: 서버 페이징. 정렬 가능 열은 로그인 아이디, 상태, 마지막 로그인, 생성일. 역할 열은 `roleCodes` 를 역할 이름으로 보이게 한다(역할 목록을 한 번 받아 코드 → 이름 매핑).
- 등록 Drawer: 로그인 아이디(필수, 영문·숫자·`._@-` 3~100자, 소문자로 저장된다는 안내), 계정 유형('ACCOUNT_TYPE' 코드), 연결할 사람(선택, 검색형 Select: 사람 목록 API, 사용 중이고 계정이 없는 사람 우선), 언어, 시간대, 초기 역할(다중 선택, 사용 중 역할). 저장하면 임시 비밀번호 모달이 한 번만 나온다.
- 임시 비밀번호 모달: 서버 응답의 `temporaryPassword` 를 크게 보이고 [복사] 버튼과 "이 창을 닫으면 다시 볼 수 없습니다. 사용자는 첫 로그인에서 비밀번호를 바꿔야 합니다" 안내를 넣는다. 화면 상태·로그·콘솔·URL·브라우저 저장소에 남기지 않고, 모달을 닫으면 메모리에서 지운다. 비밀번호 초기화도 같은 모달을 쓴다. (플랫폼 콘솔의 TemporaryPasswordModal 을 재사용할 수 있으면 재사용.)
- 기본 정보 탭: 로그인 아이디·계정 유형·상태는 읽기 전용. 수정 가능한 것은 연결된 사람, 언어, 시간대, 설명. 상세에서 잠금 종류(관리자 잠금/자동 잠금), 로그인 실패 횟수, 비밀번호 변경일·만료일을 읽기 전용으로 보인다.
- 상태 버튼: 잠금(ACTIVE → LOCKED), 잠금 해제(LOCKED → ACTIVE), 휴면(DORMANT), 휴면 해제(→ ACTIVE). 확인 대화상자에 "로그인 중인 세션이 종료됩니다"(잠금·휴면 때)를 적는다. 같은 상태로 바꾸는 버튼은 보이지 않는다.
- 역할 탭: 사용자의 역할 부여 목록(과거·미래·철회 포함, 사용 여부 필터). 열: 역할, 시작일, 종료일, 사용 여부. 편집은 [역할 편집] 모달에서 역할 선택 + 기간(선택)을 한 번에 저장한다(`PUT /users/{id}/roles` 는 교체 방식이므로 현재 사용 중 부여를 모두 채워서 보낸다). 빠진 역할은 철회된다는 안내를 한 줄 넣는다.
- 삭제/복구: 삭제는 상태가 탈퇴가 되고 세션이 끊긴다는 확인창. 복구는 상태 정상 + 비밀번호 변경 필요로 돌아온다는 안내.

## 3. 역할 화면 (`ROLE`)

```
┌ 역할 ─────────────────────────────────────────────────────────┐
│ [검색어] [사용 여부 ▼] [조회] [초기화]            [+ 역할 등록]  │
│ 코드 │ 역할명 │ 정렬 │ 사용자 수 │ 사용 │ 작업                    │
└───────────────────────────────────────────────────────────────┘
행 클릭 → Drawer [기본 정보] [권한]
```

- 기본 정보: 역할 코드(등록만 입력, 대문자로 시작하는 대문자·숫자·밑줄 2~50자), 역할명, 정렬, 설명, 이름 번역 표(NameTranslations 재사용). `TENANT_ADMIN` 은 삭제 불가·권한 편집 불가이므로 해당 버튼을 숨기고 이유를 안내한다.
- 권한 탭(매트릭스): 행 = 메뉴(사용 중 PAGE 메뉴, 서버가 주는 메뉴 정렬순, 이름은 서버 번들), 열 = 기능(READ, CREATE, UPDATE, DELETE, EXPORT 등 시드에 있는 것). 칸 = 체크박스. 해당 메뉴에 없는 기능 칸은 비워 둔다. READ 가 아닌 기능을 켜면 같은 메뉴의 READ 가 자동으로 켜진다(서버 규칙 `ROLE.READ_REQUIRED` 를 먼저 막는 UX). READ 를 끄면 같은 메뉴의 나머지가 모두 꺼진다. 행 머리를 누르면 그 메뉴 전체 켜기/끄기. [저장] 한 번으로 `PUT /roles/{id}/permissions` 에 `permissionCodes` 전체를 보낸다. 변경하지 않은 상태에서는 저장 버튼이 비활성이다. 저장 성공 후 "이 역할을 가진 사용자의 권한은 즉시 반영되지만 화면 메뉴는 다음 로그인(또는 새로고침) 때 바뀝니다" 안내.
- 삭제: 사용 중인 부여가 있으면 `ROLE.IN_USE` 서버 메시지. 복구는 UPDATE.

## 4. 단계 분할 제안

| 단계 | 내용 |
| --- | --- |
| F10 | 역할 화면(목록·기본 정보·권한 매트릭스) 먼저, 서비스·타입·메뉴 연결표 `ROLE` |
| F11 | 사용자 화면(목록·등록·임시 비밀번호 모달·상태·역할 탭) |

역할을 먼저 만드는 이유: 사용자 등록 화면의 역할 선택이 역할 목록을 쓰고, 역할 화면만으로도 "조회 전용 역할" 같은 테스트용 역할을 화면에서 만들 수 있다.

## 5. 이번 범위에서 빼는 것

- 권한(`PERMISSION`) 관리 화면: 메뉴 관리 화면과 함께 다음 묶음에서 다룬다. 기본 권한(READ, CREATE, UPDATE, DELETE, EXPORT)은 시드가 이미 갖고 있다.
- 사용자 일괄 등록, 역할 복사, 권한 변경 이력(백엔드에 이력 테이블이 없다).
- 로그인 이력·세션 목록 화면.

## 6. 합의가 필요한 항목

1. 단계를 F10 역할 → F11 사용자 순으로 나눌지(추천), 한 번에 할지.
2. 사용자 등록의 "연결할 사람" 을 선택 항목으로 둘지(서버는 선택). 시스템 계정은 사람 없이 만들 수 있다.
3. 역할 권한 편집을 매트릭스(추천) 한 화면으로 할지, 메뉴별 목록 화면으로 할지.
4. 권한 관리 화면을 이번 묶음에서 뺄지(추천).
