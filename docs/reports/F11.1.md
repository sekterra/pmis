## c. 핵심 코드

Node가 직접 실행하는 사슬만 확장자를 붙였다.

```ts
import { assertDevPortFree, resolveDevPort } from './devPort.ts';
import { applyUmiEnvFiles } from './localEnv.ts';
import { backendMissingNotice } from './proxyRules.ts';
```

`proxyRules.ts`는 `../request/tenantHeader.ts`를 읽는다. 회귀 테스트는 `.env` 적용 뒤의 포트에 `0.0.0.0`으로 먼저 바인드한 다음 `process.execPath`로 `src/core/dev/runDev.ts`를 실행한다. 포트가 이미 사용 중이면 그 상태 그대로 자식을 띄워 같은 안내로 끝나게 한다.

`engines.node`는 `>=22.18.0 <23.0.0 || >=23.6.0`이다. 23.0부터 23.5는 타입 제거가 기본이 아니라 범위에서 뺐다.

## e. 가정, 질문, 알려진 한계

- 타입 제거는 Node 22.6.0에서 추가되고, 기본 활성은 22.18.0과 23.6.0이다. `engines`를 `>=22.18.0`만으로 올리면 23.0–23.5가 포함되므로 OR 범위로 그 구간을 뺐다. `local-setup.md`의 추가 문장도 그 구간을 쓰지 말라고 적었다.
- `allowImportingTsExtensions`는 `noEmit` 또는 `emitDeclarationOnly`가 필요하다. 기존 `tsc` 스크립트가 `--noEmit`이라 `tsconfig.json`에도 `noEmit`을 넣었다. `declaration: true`는 그대로다.
- vitest와 `config/proxy.ts`의 import는 확장자가 없다. Node ESM이 읽는 파일만 바꿨다. 빌드가 `tenantHeader.ts` import를 포함한 설정을 통과했다.
- 개발 서버 기동 로그에 `DEP0190`(shell 옵션으로 인자를 넘김) 경고가 한 번 보였다. 이번 단계의 모듈 해석 수정 범위 밖이라 두지 않았다.
