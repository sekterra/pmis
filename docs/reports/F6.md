# F6단계 작업 보고서

## a. 기본 정보

- 브랜치: `main` (push 하지 않음)
- 시작 커밋: `0939dde` (`[9.2.1] 접속 주소로 플랫폼과 테넌트를 가른다`)
- 한 앱, 로그인 `/user/login` 하나. `GET /api/mdm/v1/context`의 kind로 인증 API, 홈, 메뉴를 가른다.
- `APP_MODE`, `dev:platform`, `build:platform`, 포트 8002 기본값을 제거했다.

## b. 동작

- TENANT: 제목은 `tenantName`(없으면 로고). 인증은 `/api/mdm/v1/auth`. 메뉴는 `menus/my`. 홈은 `/welcome`.
- PLATFORM: 제목은 "플랫폼 콘솔". 인증은 `/api/platform/v1/auth`. 메뉴는 "테넌트 관리"만. 홈은 `/tenants`. 서버 메뉴와 서버 언어 번들은 부르지 않는다.
- context 실패: 네트워크/5xx는 "서버에 연결할 수 없습니다"와 다시 시도. `TENANT.NOT_FOUND` 계열은 "알 수 없는 사이트입니다". 로그인 폼은 없다.
- 플랫폼 사용자의 `/mdm/**`, 테넌트 사용자의 `/tenants*`는 403. 비로그인은 `/user/login?redirect=`다.
- 플랫폼 `can()`은 항상 false. 화면 허용은 `viewFor` 한 곳이다.

## c. 검증

- `npm.cmd run lint`: biome 137파일, `tsc --noEmit`. 종료 코드 0
- `npm.cmd run test`: 29파일, 146개 통과. 약 89초
- `npm.cmd run build`: 종료 코드 0. 한 산출물에 `welcome`, `tenants`, `mdm/language`가 있다
- 개발 서버는 띄우지 않았다. `dist`는 커밋하지 않는다

## d. 질문

- 플랫폼 문구는 테넌트 로케일 모듈에 합치지 않고, kind가 PLATFORM일 때만 `extra.platform.ts`를 붙인다. 서버 번들 로딩은 테넌트 경로만 유지한다.
- CI에 플랫폼 전용 빌드 설정은 없었다.

## e. 가정

- 삭제된 플랫폼 비밀번호 화면은 테넌트 화면과 같은 변경 강제·취소·로그아웃이었다. 문구 fallback과 홈 경로만 달랐고, 홈은 이제 context를 따른다.
