# 9.3단계 작업 보고서

## a. 기본 정보

- 브랜치: `main` (push 하지 않음)

- 메뉴 관리 API와 관리자 잠금 보완. DDL 변경 없음.

## b. 동작

- 상태 API로 `LOCKED`를 걸면 `lockedDatetime`은 null이다. `lockType`은 `ADMIN`이다. `LOCK_MINUTES`가 지나도 로그인은 거절된다. `lockedDatetime`이 있는 자동 잠금만 시간이 지나면 풀린다. `ACTIVE`와 비밀번호 초기화는 잠금을 푼다.
- `GET/POST/PUT/DELETE /api/mdm/v1/menus`, `GET /menus/tree`, `PUT /menus/sort-orders`, `POST /menus/{menuPk}/restore`. `{menuPk}`는 숫자만 받는다. 권한은 `MENU`의 READ/CREATE/UPDATE/DELETE.
- PAGE 등록 시 기능 권한 5개를 만든다. 시드 메뉴 삭제는 `MENU.PROTECTED`. 메뉴 이름은 네임스페이스 `menu` 메시지다. `menuPath`는 시드와 같은 코드 경로다.

## d. 질문

- ERD의 `menu_path` 예시(PK 경로)와 시드(코드 경로)가 달라 시드를 따랐다.
- 상위 메뉴는 같은 솔루션 GROUP만 허용했다.
- `solutionCode`의 네임스페이스 존재 여부는 검사하지 않았다.
- 새 메뉴 코드를 요구하는 API가 없어 삭제 직후 효과는 `menus/my`와 권한 행 회수로 확인했다.
