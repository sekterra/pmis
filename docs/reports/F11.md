## e. 가정, 질문, 알려진 한계

- 초안은 계정이 없는 사람을 우선한다. 지시서는 사용 중 사람 검색과 서버의 연결 거절을 사람 칸에 보이라고 한다. 지시서를 따랐고 `frontend/doc/f11-wireframe.md`에 적었다.
- 본인 행 버튼은 숨긴다. 비활성으로 두지 않는다.
- 수정 DTO의 `clearPerson`은 서비스가 읽지 않는다. 연결 해제는 `personPk: null`이다.
- `ROLE.INACTIVE` 필드는 `roleCode`뿐이라 행을 특정하지 못한다. 편집 창 안내에 보인다. 필드가 역할 코드면 그 행 옆에 보인다.
- `ROLE.NOT_FOUND`와 `ROLE.INVALID_DATE`도 필드가 없어 편집 창 안내로 보인다. 종료일이 시작일보다 빠르면 요청 전에 그 행에서 막는다.
- 플랫폼 `TemporaryPasswordModal`은 로그인 아이디 복사와 문구 구조가 달라 옮기지 않았다. 사용자용은 `IssuedPasswordModal`이다.
- 생성일 정렬은 API 화이트리스트에만 두고 열은 만들지 않았다.
- 역할 목록은 페이지가 없다. 같은 사용자·필터·갱신 키면 다시 받지 않는다.
- 부모 그룹은 서버 `menus/my`의 `parentMenuCode`를 쓴다.
- 사용자가 직접 볼 항목은 `frontend/doc/f11-manual-check.md` 맨 위에 있다.
