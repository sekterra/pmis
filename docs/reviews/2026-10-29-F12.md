# F12 검토 (2026-10-29)

판정: 승인(자동 검증 기준). 실제 서버 수동 확인 전에 아래 보완을 다음 프론트 단계에 포함한다.

## 확인한 것
- 티켓은 `#ticket=` 를 읽자마자 주소창에서 지우고 교환하며, 티켓과 accessUrl 은 컴포넌트 상태에만 둔다. 지원 세션은 refresh 를 시도하지 않고 401 이나 `AUTH.SUPPORT_ENDED` 이면 종료 화면으로 간다. 새로고침하면 메모리 토큰이 없어 종료 화면이 나온다(설계대로).
- `sessionStorage` 에는 값이 없는 플래그(`mdm_support_session`)만 저장한다. 토큰이나 티켓은 저장하지 않는다.
- 발급 모달은 2단계(사유 → 링크와 60초 카운트다운), ACTIVE 테넌트에서만 버튼 표시. 비밀번호 변경 메뉴는 지원 세션에서 숨김. 기록 화면 2개는 공용 컴포넌트.
- lint, antd lint, tsc 통과. 테스트 59파일 230개 통과, 새 흐름 3회 반복 통과, build 통과.

## 보완
1. 진입 화면(`pages/support-access/index.tsx`)의 effect 는 주소의 티켓을 지운 뒤 교환한다. React StrictMode 로 effect 가 두 번 실행되면 첫 실행은 `cancelled` 로 결과를 버리고, 두 번째 실행은 티켓이 이미 지워져 "유효하지 않은 접속 주소"가 된다. 티켓은 이미 소모되어 다시 쓸 수 없다. 교환 호출을 모듈 수준의 한 번만 실행되는 약속(promise)에 담아 두 실행이 같은 결과를 쓰게 하고, 이 경우를 테스트한다(StrictMode 로 렌더).
2. dev 에서 `X-Tenant-Code` 는 교환 요청에만 붙는다. 이후 `me`, 메뉴 등 요청에 테넌트가 어떻게 전달되는지(토큰의 tenant 클레임만으로 충분한지, dev 프록시가 헤더를 넣는지) 코드로 확인하고, 필요하면 지원 세션에서도 같은 테넌트 코드를 보낸다. 확인 결과를 보고서에 적는다.
3. 기록 화면(플랫폼·테넌트) 전용 흐름 테스트가 없다. 목록 조회 → 필터 → 행 클릭 Drawer 의 액션 목록 → 권한별 접근을 하나씩 추가한다.
4. 코드 정리: `setView(code === ... || code ? 'invalid' : 'invalid')` 는 조건이 의미 없다. 하나로 정리한다.
5. `F12.diff` 가 UTF-16 으로 저장되어 도구로 바로 읽히지 않았다. 앞으로 보고서 `.md`, `.diff` 는 UTF-8 로 쓴다(PowerShell 의 `>` 리디렉션 대신 `git diff ... | Out-File -Encoding utf8` 또는 `--output` 옵션).
