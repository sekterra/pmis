- 날짜: 2026-10-19
- 대상: 보고서 docs/reports/9.3.md (시작 3205148), 변경 24개 파일, DDL 변경 없음
- 결과: **승인** (작은 보완 3건은 9.4 지시서 A절로 넘김)

## 확인한 것
- 관리자 잠금: `UserAccountService` 가 LOCKED 전환 시 `locked_datetime=NULL`, ACTIVE 도 NULL. `lockType`(ADMIN | AUTO | null)을 단건 응답에 추가. `LoginLockRules.expired(null, …)` 가 항상 false 라는 단위 테스트 추가. 통합 테스트가 관리자 잠금 유지와 ACTIVE 복구를 확인한다.
- 메뉴 API: 목록·트리·단건·등록·수정(이동)·정렬 일괄·삭제·복구. 등록 코드 전체 유니크(삭제 코드 재사용 불가), PAGE 경로 중복, 깊이 4, 상위 GROUP·같은 솔루션 검증, 타입·코드·솔루션 변경 거절. 상위가 같으면 상위 재검사를 하지 않는다.
- PAGE 등록 시 기능 권한 5개 생성, 삭제 시 permission·role_permission 회수, 복구는 권한 비복구. 시드 메뉴는 `SeedMenuCodes` 가 S05 의 menu INSERT 에서 코드를 읽어 보호하고, 읽지 못하면 solution `MDM` 으로 대체(안전한 쪽).
- 메뉴 이름 번역은 8.4 읽기 경로와 같은 네임스페이스 `menu` 메시지에 upsert. 변경 후 권한 캐시와 menu 번들 캐시를 비운다.
- 통합 테스트가 새 PAGE 메뉴 → 역할 권한 부여 → `menus/my` 즉시 반영, 삭제 시 즉시 사라짐, 권한 없는 사용자 403, 테넌트 분리, 일괄 업그레이드 문구 추가·보존을 확인한다. 단위 76, 통합 42 통과, DB 이름 `pmis`.
- 질문 3건(시드 `menu_path` 코드 경로 채택, 같은 솔루션 GROUP 만 상위 허용, `solutionCode` 네임스페이스 존재 미검사)은 모두 현 상태로 확정.

## 보완 (9.4 A절)
1. **LIKE 와일드카드**: `moveDescendants`/`assertDepth` 가 `menu_path LIKE '<oldPath>/%'` 를 쓴다. 메뉴 코드는 `_` 를 허용하므로(`OPS_BOARD`) `_` 가 와일드카드로 동작해 다른 메뉴의 자손까지 갱신할 수 있다(예: `/A_B` 이동이 `/AxB/...` 에 영향). 접두사 비교를 LIKE 이스케이프나 `left(menu_path, n) = ?` 로 바꾸고 `_`·`%` 가 든 코드로 회귀 테스트를 추가한다.
2. 보고서 질문 4번("새 메뉴 코드를 요구하는 API가 없어 …")은 실제로는 통합 테스트가 이미 `PUT /roles/{id}/permissions` 로 검증하고 있어 문제 아님. 보고서 문구만 정정.
3. 사소한 서식: `UserAccountService.response` 의 탭 문자 섞임 정리. `MenuAdminService.route` 의 `"GROUP".equals(type) ? route : route` 불필요한 삼항 제거.

## 메모
- 목록의 상위 코드 조회는 페이지의 서로 다른 상위마다 `findById` 를 한다(영속성 컨텍스트 캐시로 대부분 흡수). 규모가 커지면 IN 조회로 바꾼다.
- 새 PAGE 메뉴는 프런트 `menuRoutes.ts` 매핑이 없으면 이동 시 404 화면이다(문서에 한계로 기록됨).
