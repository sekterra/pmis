# 9.4단계 검토 (2026-10-19)

대상: `docs/reports/9.4.md`, `9.4.diff` (시작 커밋 19e3d0b), 핵심 코드 `FileService`, `FileRules`, `LocalFileStore`, `AttachmentService`.

## 결론

승인. 지시서 항목(9.3 LIKE 보완, 저장소, 업로드·다운로드, 첨부, 프로필 이미지, 팀·팀원, 오류 코드, 문서, 테스트)이 모두 반영되었고 단위 81건·통합 44건이 통과했다. 아래는 막는 문제가 아니라 다음 단계 A절로 넘기는 보완 항목이다.

## 확인된 좋은 점

- 메뉴 경로 비교를 `left` 로 바꿔 `A_B`/`AXB` 문제를 고쳤다.
- 파일 응답에 저장 경로가 없고, 저장 키는 `YYYY/MM/UUID`, 테넌트 폴더로 분리, `resolveFile` 이 `..` 와 경로 이탈을 막는다.
- 쓰기는 `.uploading` 임시 파일 후 원자적 이동이고, DB 저장 실패 시 디스크 파일을 지운다.
- 확장자 이중 검사(`a.exe.txt`), 위험 확장자 차단, 비밀 키 이름이 든 연결 설정 거부(`FILE.SECRET_IN_CONFIG`).
- TEMP 파일은 올린 사람만 연결·다운로드할 수 있고, 사용 중인 파일은 삭제할 수 없다(`FILE.IN_USE`).

## 보완 항목 (다음 단계 A절)

1. **MIME 검사 허점**: `FileRules.assertMime` 은 내용 판별(`sniff`)이 null 이면 통과한다. 이미지 확장자(png/jpg/gif/webp)와 pdf 는 판별 실패를 거부해야 한다. 지금은 `x.png` 에 임의 바이트를 넣어도 프로필로 지정된다. (`nosniff` 헤더 덕에 실제 피해는 작다.)
2. **목록 검색어 와일드카드**: `FileService.filter` 의 `keyword` 가 `%`, `_` 를 이스케이프하지 않는다. 9.3 과 같은 종류다. 공통 이스케이프 유틸로 정리하고 다른 목록 검색(회사·부서·사람·팀·사용자)도 함께 점검한다.
3. **정리 작업 집계**: `cleanup` 은 이미 지운 파일(DELETED, 디스크 없음)도 실행할 때마다 `purged` 로 센다. 디스크 삭제 뒤 행을 표시(예: 예약 시각 NULL)해서 한 번만 세게 한다. DDL 변경이 필요하면 먼저 보고한다.
4. **고아 파일**: 디스크 쓰기 뒤 트랜잭션 커밋이 실패하면 디스크 파일이 남는다. 트랜잭션 완료 후 롤백이면 지우는 훅을 추가한다.
5. **메모리**: 업로드·다운로드가 전체 바이트를 메모리에 올린다. 최대 크기 상한이 있어 지금은 허용하지만, 다운로드는 스트리밍으로 바꿀 후보로 기록만 한다.

## 질문 답변 (보고서 d절)

- 일반 사용자 업로드 권한: `FILE:CREATE` 만 허용하는 현재 구현 유지.
- 정리 자동 실행: 지금은 수동 API 유지. 운영 단계에서 설정으로 켜는 스케줄러를 만든다.
- 팀당 LEADER 1명 제한: 두지 않는다.
- 사람 삭제 시 팀원: 기존 규칙 유지(이력 보존). 화면에서 비활성 사람을 표시한다.
- 팀 코드 형식 `^[A-Z0-9_-]{1,50}$`: 승인.
