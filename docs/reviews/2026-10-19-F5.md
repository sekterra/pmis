# F5단계 검토 (서버 메뉴 menus/my와 실제 권한 연결)

결과: 승인

- 보고서 `docs/reports/F5.md`와 diff를 읽고 확인했다. 커밋 `42b5763`, push 없음, `git status` 깨끗.
- 사이드 메뉴가 `menus/my`로 만들어지고(`buildSideMenu.ts`), 서버 `routePath`는 쓰지 않고 `menuRoutes.ts` 연결표 한 곳(COMMON_CODE, I18N 두 화면)으로 연결됨. 표에 없는 메뉴 제외, 빈 그룹 숨김, 정렬 규칙이 지시서대로.
- 권한: `access.ts`의 `can`이 `actions`로 판정하고 로딩 전·실패는 false. 임시 허용 `permission.ts` 세 개가 삭제되고 화면이 `useAccess().can`을 직접 씀.
- 진입 가드: 연결표에 있는 경로에서 READ가 없으면 403 화면, 로딩 중 본문 없음, 실패는 다시 시도 안내. 표 밖 경로는 가드 제외.
- 로딩 시점: 로그인, 세션 복구, 언어 변경, 비밀번호 변경 후. 강제 변경 상태에서는 호출 안 함. 로그아웃·401 이동·다른 탭 로그아웃에서 비움. 진행 중 요청 재사용.
- 플랫폼 빌드: `runtime.platform.tsx`로 대체되어 `menus/my`와 연결표가 산출물에 없음(문자열 검색 0건). 메뉴·토큰은 메모리만.
- 검증: lint, antd lint, tsc 통과. 전체 테스트 30파일 141개, `core/menu/flow.test.tsx` 3회 반복 11개 통과. build, build:platform 정상. 새 라이브러리·백엔드 수정 없음.

비차단 메모(필요해지면 별도 지시):
1. 메뉴 조회가 진행 중일 때 언어를 바꾸면 진행 중이던 요청(이전 언어)이 재사용되어 메뉴 이름이 한 번 이전 언어로 남을 수 있다. 다음 로딩 시점에 바로잡힌다.
2. 서버가 비밀번호 변경 필요(`AUTH.PASSWORD_CHANGE_REQUIRED`)를 돌려 메뉴가 idle로 남은 상태에서 연결표 경로를 열면 로딩 표시가 계속된다. 실제로는 비밀번호 변경 화면으로 보내지므로 드문 경우다.
3. 아이콘 이름 표는 5개뿐이고 그 밖의 이름은 기본 아이콘이다. 서버 Seed의 iconName이 정해지면 표를 늘린다.

사용자 직접 확인(`frontend/doc/f5-manual-check.md`): 실제 서버 `menus/my` 응답으로 사이드 메뉴가 나오는지, TENANT_ADMIN과 권한이 적은 사용자 비교, 직접 주소 접근 시 403, 언어 변경 시 메뉴 이름, 사용감.
