# 9.7 · 9.8 검토 (2026-10-29)

판정: 승인. 아래 보완 3건은 다음 백엔드 단계에 함께 처리한다.

## 9.7 개발 전용 관리자 계정 명령
- 개발 프로필 검사, DB 이름 검사, 값은 환경변수로만 받음, 비밀번호 정책은 이 명령에서만 건너뜀, 출력에 비밀번호 없음: 지시대로 구현됨.
- 테넌트 코드 생략 규칙(ACTIVE 1개일 때만, 결과 줄에 적용 코드 출력) 반영됨.
- 단위 89, 통합 53 통과. target=platform 은 공유 테이블 고정이라 단위 검증만 한 점은 수용한다.

## 9.8 지원 접속
- 티켓: 256비트 난수, SHA-256 해시 저장, 60초, 조건부 UPDATE 로 한 번만 교환, 모든 실패가 같은 401.
- 토큰: `sup`, `act` 클레임, 30분, refresh 없음. 매 요청 세션 필터가 접속 행 상태·만료·운영자 활성·테넌트 일치를 확인.
- 쓰기 요청은 처리 전에 별도 트랜잭션으로 기록하고 실패하면 503 으로 거절. 종료 API 와 조회는 기록하지 않음.
- 시스템 사용자 `$platform-support`: 목록·검색에서 제외, 변경 거절(`USER.SYSTEM_ACCOUNT`), 로그인 불가, 마지막 관리자 판정에서 제외(테스트 있음). 비밀번호 변경은 `AUTH.SUPPORT_FORBIDDEN`.
- 접속 기록은 공용 스키마, 삭제·수정 API 없음. 테넌트 조회는 서버에서 테넌트 조건을 강제.
- 단위 92, 통합 61 통과(공용 ERD 에 두 테이블이 없어 실패한 마이그레이션 테스트 2건은 ERD 추가로 해결).

## 보완 (다음 백엔드 단계)
1. 보고서는 "60초 캐시를 두지 않았다"고 하나 `SupportAccessService.requireSession` 에 60초 캐시가 있다. 종료·폐기가 DB 에서 직접 바뀌면 최대 60초 늦게 반영될 수 있다. 의도라면 문서에 적고, 아니면 캐시를 줄이거나 제거한다.
2. `SupportAuditStore.failNextInsert()` 는 테스트용 훅이 운영 클래스에 있다. 테스트 전용 구성(테스트 소스의 대체 빈 등)으로 옮긴다.
3. 만료된 ACTIVE 행이 그 토큰으로 다시 요청이 오지 않으면 영원히 ACTIVE 로 남는다(응답만 EXPIRED 로 계산). 조회 화면은 맞게 보이지만 저장 상태가 어긋난다. 정리 방법(조회 시 갱신 또는 주기 정리)을 정한다.

## 질문에 대한 답
- 메뉴를 `SYSTEM` 아래에 둔 것: 수용(시드에 `ACCESS` 그룹이 없음). 프론트는 서버가 준 부모 메뉴를 따른다.
- 운영자 비활성화 API 없이 요청마다 확인: 수용.
