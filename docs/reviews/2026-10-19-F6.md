# 검토: 프런트 F6단계 (한 앱·한 로그인 화면)

- 날짜: 2026-10-19
- 대상: 보고서 docs/reports/F6.md (시작 0939dde), 변경 약 40개 파일
- 결과: **승인** (작은 보완 2건은 다음 프런트 단계에 포함)

## 확인한 것
- `core/auth/context.ts`: 앱 시작 때 `GET /api/mdm/v1/context` 를 받아 kind 를 메모리에만 두고, 인증 경로·쿠키 이름·홈 경로가 모두 이 값에서 나온다. 실패는 `offline`(네트워크/5xx)과 `unknown`(`TENANT.NOT_FOUND/UNRESOLVED/INACTIVE`)로 나뉘고 둘 다 로그인 폼을 보이지 않는다.
- `app.tsx`: context 가 `ready` 일 때만 언어 번들 로딩과 세션 복구가 시작된다. 기존 `sessionApi` 분기가 `authApi` 어댑터 하나로 정리됐다.
- 메뉴: PLATFORM 은 서버 메뉴를 부르지 않고 정적 "테넌트 관리" 하나, `can()` 은 항상 false, TENANT 는 기존 `menus/my`. 가드는 `areaForbidden` + `viewFor` 한 곳.
- `APP_MODE`, `dev:platform`, `build:platform`, 포트 8002, `routes.platform.ts`, 플랫폼 전용 로그인·비밀번호 화면이 제거됐다.
- lint, 타입 검사 통과, 테스트 29파일 146개 통과, 빌드 통과. 개발 서버 실기 확인은 아직 없다(사용자 확인 문서 `frontend/doc/f6-manual-check.md`).

## 보완 (다음 프런트 단계에서)
1. `areaForbidden` 이 플랫폼 로그인 상태에서 `/mdm/**` 만 막는다. 플랫폼 운영자가 `/welcome` 으로 가면 테넌트용 환영 화면이 보인다. 플랫폼 로그인 상태에서는 `/welcome` 도 `/tenants` 로 보내거나 403 으로 막는다.
2. `TENANT.INACTIVE` 도 "알 수 없는 사이트입니다" 로 보인다. 운영 중단 테넌트에는 별도 안내가 낫다(필수 아님, 사용자 결정).

## 사용자 확인 필요
- `DEV_TENANT_CODE` 설정/비움 두 상태로 로그인해 보기, 플랫폼 로그인 후 `/mdm/language` 직접 입력(403), 서버를 끈 상태의 연결 안내 (`f6-manual-check.md`).
