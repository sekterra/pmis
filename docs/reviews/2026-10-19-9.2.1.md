# 검토: 백엔드 9.2.1단계 (접속 주소 컨텍스트 조회)

- 날짜: 2026-10-19
- 대상: 보고서 docs/reports/9.2.1.md (시작 e8f73dd)
- 결과: **승인**

## 확인한 것
- `AccessContextService.resolve`: dev 프로필에서만 `X-Tenant-Code` 헤더를 읽고, 그다음 `mdm.platform.hosts`, 마지막으로 `tenant_domain` 순이다. 지시서 순서와 같다. 응답은 `kind`, `tenantCode`, `tenantName`뿐이고 null 은 빠진다.
- `PlatformHostFilter`: 목록이 비어 있지 않을 때만 `/api/platform/**` 를 걸러 목록 밖 Host 는 404 `TENANT.NOT_FOUND`(존재를 드러내지 않음). 목록이 비면 제한 없음.
- `TenantResolutionFilter` 제외 목록에 `/api/mdm/v1/context` 한 줄만 추가. 다른 경로 동작 불변. DDL 변경 없음.
- 단위 74, 통합 40 통과. 통합 테스트가 `t_it_` 스키마를 정리하고 실제 `pmis.tenant` 행 수 불변.

## 메모
- 질문(플랫폼 Host 거절에 새 오류 코드 없이 `TENANT.NOT_FOUND` 재사용): 이대로 확정.
- 운영 배포 전 `MDM_PLATFORM_HOSTS` 를 정해야 한다(예: 별도 관리 호스트). 비워 두면 플랫폼 API 가 모든 Host 에서 열린다.
- Host 는 서블릿이 본 값이다. 리버스 프록시 뒤에서 Host 가 바뀌면 `X-Forwarded-Host` 처리(서버 forward-headers 설정)가 맞아야 한다. 배포 시점 점검 항목으로 남긴다.
