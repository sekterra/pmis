# F7단계 검토 (2026-10-22)

대상: `docs/reports/F7.md`, `F7.diff` (시작 커밋 d8f3e52, 구현 커밋 db94564), 핵심 코드 `companyQuery.ts`, `companyRecord.d.ts`, `rules.ts`, `useCodeOptions.ts`.

## 결론

승인(자동 검증 기준). 지시서 항목이 모두 반영되었고 lint, antd lint, tsc, 테스트 158개, build 가 통과했다. 사용자의 화면 직접 확인(수동 확인 문서)은 아직 하지 않았다. 확인 결과는 F8 이후에 함께 반영한다.

## 좋은 점

- 서비스, 쿼리 변환, 규칙, 화면이 분리되어 있고 서비스 목 테스트로 흐름을 검증한다.
- 수정 본문에 회사 코드가 없고, 빈 값은 null, 번역은 입력한 언어만 보낸다.
- 플랫폼 영역에서 `/org` 를 막고, 부모 메뉴 그룹은 서버 응답을 따른다.
- 공통코드·다국어 화면은 건드리지 않았다.

## F8 로 넘기는 보완

1. `useCodeOptions` 캐시가 로그아웃, 계정 전환, 다른 테넌트 로그인에서도 남는다. 재설정 연결이 필요하다.
2. 회사 오류 문구가 `rules.ts` 에 한글로 하드코딩되어 있다. 로컬 i18n 키로 옮긴다.

## 알아둘 점 (조치 없음)

- 수정 때 화면에 없는 필드(법인등록번호, 대표자, 주소 등)를 상세 값으로 다시 보낸다. 다른 사람이 같은 시각에 바꾼 값을 덮을 수 있으나 동시 수정 충돌 처리는 이 시스템 전체에 아직 없다. 지금 범위에서는 허용한다.
- `build:platform` 스크립트가 F6 에서 없어졌으므로 플랫폼 영역 차단은 `areaForbidden` 테스트로 확인한다.
- 사용자의 수동 확인(관리자/조회 전용 계정 비교)은 보류되었다.
