## 결론

승인(자동 검증 기준). lint, antd lint, tsc, 테스트 189개, build 가 통과했다. F8 보완(늦은 응답 덮어쓰기, 변경 유형 문구 i18n)도 반영되었다. 화면 직접 확인은 보류 상태다.

## 좋은 점

- 업로드는 `FormData` 의 `file` 필드만 보내고 Content-Type 을 직접 쓰지 않는다. 요청 계층 변경이 작다(`headersForBody`, `rawBlob`, `toBlobApiError`).
- 프로필 이미지는 인증 헤더가 필요한 점을 blob URL 로 풀었고, Drawer 를 닫거나 사람이 바뀔 때 URL 을 해제한다. 404 는 오류가 아니라 사진 없음으로 처리한다.
- 소속 규칙(퇴직 종료일, 부서 없는 부서장, 첫 소속 안내)과 오류 → 칸 매핑이 순수 함수로 분리되어 테스트된다.
- 부서 화면의 소속 인원 행에서 사람 화면으로 이동하는 연결이 PERSON:READ 가 있을 때만 동작한다.

## 다음 단계로 넘기는 보완

1. **소속 목록 조회가 사람 객체 변경에 취약하다** (`PersonDrawer.tsx` 소속 목록 effect). 의존성에 `person` 객체가 들어 있고 같은 조회 키를 이미 시작했다는 이유로 재호출을 건너뛴다. 조회 도중 `person` 객체가 새로 만들어지면(저장 후 새로고침 등) 이전 요청의 결과는 `alive=false` 로 버려지고 새 요청은 건너뛰어, 소속 표가 비어 있는 채로 남을 수 있다. 의존성을 `person?.personPk` 같은 값으로 바꾸고, 이 순서를 재현하는 테스트를 추가한다.
2. 사람 화면의 사진 유무 표시는 목록 `hasProfileImage` 로만 판단한다. 사진을 올린 직후 목록이 새로고침되는지 수동 확인 항목에 넣는다(확인만, 코드 변경 없음).

## 알아둘 점 (조치 없음)

- 소속 등록은 `PERSON:CREATE`, 삭제는 `DELETE`, 수정·종료·복구는 `UPDATE` 로 판정한다. 백엔드 명세와 맞는지 수동 확인에서 권한이 적은 계정으로 본다.
- 프로필 올리기의 두 번째 호출(연결)이 실패하면 업로드한 파일은 TEMP 로 남는다. 서버 정리 스케줄러가 처리한다(운영에서 켠 경우).
- 업로드 크기 검사는 문서 기본값 50MB 이고 저장소 한도는 서버 문구로 받는다.
- 전체 테스트 시간은 약 262초로 F8 과 같다.
